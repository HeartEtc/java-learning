#### W2 已记录的教训

> **D1 教训一（`static` 误用）**：把 `Library` 的 `bookCount`/`userCount`/`loanCount` 写成了 `static`。
> 后果：两个 `Library` 实例会共享计数，新建一个图书馆会把另一个的计数清零。
> **判据：数据是"每个对象各自一份" → 实例字段；"全系统共用一份" → `static`。**
> `Library.bookCount` 属于某一家图书馆（实例字段）；`Loan.totalLoans` 才是全系统累计（static）。

> **D1 教训二（两个同类型参数传反）**：`Book` 构造器声明为 `(isbn, id, ...)`，调用方按 `(id, isbn, ...)` 传——**编译器完全不报错**，运行时 `findBookById("B001")` 永远找不到。
> **对策：主键/最重要的参数放第一位，靠位置区分；打开 IDEA 的 `Inlay Hints → Parameter names`。**
> 这条已加入验收：**发现"数据明明加进去了却查不到"，第一件事是打印字段的实际值，而不是怀疑查找逻辑。**

> **D1 教训三（复制粘贴残留）**：`UserNotFoundException` 里的构造器抄成了 `BookNotFoundException`；`aaa_messages.java` 类名全小写。
> **改模板后必须回头念一遍新名字。**

> **D1 教训四（`equals` 的方向）**：`id.equals(book.getId())` 中 `id` 可能为 `null` → `NullPointerException`，而期望的是 `BookNotFoundException`。
> **规则：`equals` 用在"确定非 null"的一方；不确定的当参数。** 或用 `Objects.equals(a, b)`。

#### W2 新增概念备忘

| 概念 | 结论 |
|---|---|
| 自定义异常继承谁 | `RuntimeException`（非受检）。理由：ID 不存在属于"调用方传参错误"，不该强制每个调用方 `try-catch` |
| 构造器里的 `super(message)` | **必须写**，否则 `getMessage()` 返回 `null`，消息丢失 |
| 包与目录 | `package com.example.library.exception;` ↔ `src/com/example/library/exception/`，必须一致 |
| `import` | 跨包使用必须 `import`；**同包不需要** |
| 可见性默认值 | 不写修饰符 = 包级私有。**默认从 `private` 开始，需要时再放宽** |
