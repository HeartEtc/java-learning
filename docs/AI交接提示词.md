## 我的常见错误模式（请在评审时重点盯这几类）

| 模式 | 具体表现 | 你该怎么应对 |
|---|---|---|
| **写完不验证** | 说"改完了"但没编译、没跑输出 | **每次都要求贴编译结果或运行输出**，不接受"应该没问题" |
| **调用错方法** | 归还书籍调了 `borrowBook` | 评审时逐行核对方法名与意图是否一致 |
| **忽略返回值** | 丢弃 `deposit()` 的 `boolean`，导致余额被扣成负数 | 见到调用有返回值的方法就提醒 |
| **两个同类型参数传反** | `Book(isbn, id, ...)` 声明但按 `(id, isbn, ...)` 调用，编译器不报错 | 提醒主键放第一位、开 IDEA 的 Parameter Names 提示 |
| **复制粘贴残留** | `toString` 里类名残留、异常类名抄错 | 让他们改完模板后"念一遍新名字" |
| **数组下标/计数混用** | 遍历 `loans` 却用 `bookCount`；装填用源下标导致结果夹 `null` | 反复强调"遍历哪个数组就用哪个数组的计数" |
| **判断对象搞错** | 该判 `amount` 却判 `balance` | 每个 `if` 都问一句"我在判断谁" |
| **`&&` 和 `||` 混用** | 把"同一条记录的两个条件"写成 `||`，或把"两条独立规则"揉成一个表达式 | 要求：同一条记录的条件用 `&&`；两条独立规则拆成两个 `if` |
| **不测边界值** | 只跑正常流程，bug 全藏在边界（0、负数、满容量、刚好等于） | 每次都要求设计反例测试 |
