# 大一年度项目：三人分工方案

> 制定：2026-10-11
> 项目：数据驱动的机场调度优化（见 `大一年度项目-需求与设计.md`）
> 成员技能：
> **A（本人）**：Java 有基础（写过 P1 图书管理系统，7 个类）；无 Python / SQL / R
> **B**：会 Python + MySQL
> **C**：编程零基础

---

## 1. 核心原则

**① 数据只在一处加工，下游只消费上游的产物。**
**② 每人负责一段"有交付物"的环节，不设"打杂位"。**

```
原始数据  ──A──▶  清洗后 CSV  ──B──▶  MySQL  ──B──▶  统计结果 CSV  ──B/C──▶  R 图表  ──共同──▶  报告
          (Java)              (Python+SQL)         (SQL)              (R)
                    ↑                                            ↑
                    └────────── C：数据校验 + 报告 ──────────────┘
```

---

## 2. 三人分工

### A（本人）｜Java 侧：原始数据 → 清洗后数据

| 任务 | 交付物 |
|---|---|
| 从老师处接收原始数据，确认字段含义 | 数据说明（字段清单） |
| 用 **Java** 读入原始数据（`BufferedReader` / IO） | `RawFlightLoader` 类 |
| 数据清洗：丢弃缺失/非法记录，统一时间与字段格式 | `flights_clean.csv` |
| 统计"丢了多少条、为什么丢" | 清洗日志 |

**为什么这段给 A**：需要写 Java 代码，而 A 是唯一有 Java 基础的人。**且这段正好用上 A 正在学的 IO（W4）。**

**技术要点**：`List<Flight>` / `ArrayList` / `HashMap` 分组 / `LocalDate` 解析 / 异常处理 —— **全部是 A 已学或本周要学的内容**。

---

### B｜Python + MySQL 侧：清洗后数据 → 统计结果

| 任务 | 交付物 |
|---|---|
| 搭建 MySQL 库表（`flights` 表 + 索引） | 建表 SQL 脚本 |
| 用 **Python** 把 `flights_clean.csv` 导入 MySQL | `import_to_mysql.py` |
| 用 **SQL** 做分组统计：按小时、按航线 | `hourly_stats.csv`、`route_stats.csv` |
| 编写"调整规则"对应的 SQL（筛选高峰时段航班） | 调整后统计 CSV |
| 环境的安装文档（让组员能复现） | `docs/环境说明.md` |

**为什么这段给 B**：**SQL 分组聚合是 B 的现成技能**，而且 `GROUP BY ... AVG(delay) ... COUNT(*)` 正是本项目统计量最自然的实现方式——**比 Java 手写循环更短更清晰**。

**附带价值**：B 顺便把"CSV 导入数据库"这条链路跑通，这是**真实数据岗每天在做的事**。

---

### C｜数据校验 + 报告（编程零基础也能承担，但不是打杂）

| 任务 | 说明 |
|---|---|
| **字段含义表** | 把原始数据里每个字段抄录、注明含义与单位（老师给的说明整理成表） |
| **数据抽样核对** | 用 Excel 打开原始数据，随机抽 20 行，**手工核对** A 的清洗结果对不对（哪些该丢、是否真丢了） |
| **异常值记录** | 记录明显不合理的数据（如延误 9999 分钟、日期越界） |
| **对比图制作** | 用 Excel 根据 B 导出的 CSV 做初步图表（后面 R 再美化） |
| **报告撰写** | 项目背景、数据来源与字段说明、数据质量问题汇总 |
| **答辩材料** | 整理 PPT、排练计时 |

**为什么这些不是打杂**：

- **数据核对是数据项目里最容易被跳过、也最容易出事的一步**。三个人做的统计如果没人核对，出错了全体背锅
- 字段含义表**是报告里必需的章节**，也是每个人理解数据的前提
- 报告撰写**必须有人专门负责**，否则最后一周全员赶稿

**给 C 的成长路径**：先从 Excel 开始，如果能上手，**下一步让 B 带他学 `pandas` 读 CSV 做同样的核对**——这是零基础最自然的编程入口。

## 3. 文件流程与命名约定（避免"文件满天飞"）

| 阶段 | 文件 | 产出者 | 消费者 |
|---|---|---|---|
| 0 | `data/raw/flights_raw.csv` | 老师 | A |
| 1 | `data/output/flights_clean.csv` | **A** | B |
| 2 | `data/output/hourly_stats.csv` | **B** | C（画图/核对） |
| 2 | `data/output/route_stats.csv` | **B** | C |
| 2 | `data/output/hourly_stats_adjusted.csv` | **B** | C |
| 3 | `report/figures/*.png` | B / C | 全体 |
| 4 | `report/报告.docx` | **C** 主笔，全体补充 | — |

**约定**：
- 所有 CSV **UTF-8 无 BOM**
- 列名固定，**改列名必须提前在群里说**
- **原始数据不进 Git**（可能几十 MB）；放一份 100 行的样例在 `data/sample/` 里

## 4. 答辩分工（每人必须能讲自己那一段）

| 人 | 讲什么 | 会被问到的问题 |
|---|---|---|
| **A** | 数据处理流程、清洗规则、Java 实现 | "清洗丢了多少条？判定标准是什么？" |
| **B** | 数据库设计、SQL 统计逻辑、调整规则 | "高峰时段怎么定义？为什么用这个 SQL？" |
| **C** | 数据来源与字段含义、数据质量发现、结论与建议 | "你们的调整建议依据是什么？" |

**共同要能回答**：**"你们三个人怎么协作的？"**
标准答案：**"我们用 CSV 作为各环节之间的接口，每段只加工一次，避免两人算出不同数字。"** —— 这是加分的答法。

---

## 5. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| **统计量两边各算一遍** | 报告里数字对不上 | 统计只在 B 的 SQL 里做一次，A 和 C 不重复实现 |
| **C 没事干 / 边缘化** | 老师看出来，C 答辩答不上 | C 的核对与报告任务是**硬需求**，每周要有产出 |
| **B 的环境搭不起来** | 卡住一周 | **第一周就把环境文档写出来**，A、C 也要能跑起来验证 |
| **数据迟迟拿不到** | 整个项目停摆 | **先用自造数据**（A 造 20 行）把整条链路跑通，真数据到了只换文件名 |
| **字段含义不清** | 统计口径错 | **C 的字段含义表是前置任务**，第一周完成 |

---

## 6. 时间线（建议）

| 时间 | A | B | C |
|---|---|---|---|
| 第 1 周 | 造 20 行样例数据；写清洗程序 | 搭 MySQL + 写导入脚本 | 整理字段含义表 |
| 第 2 周 | 接真数据，产出 `flights_clean.csv` | 写 SQL 统计，产出两份 CSV | 抽样核对清洗结果 |
| 第 3 周 | 补充数据质量问题的处理 | 调整规则 + 调整后统计 | Excel 初步出图 |
| 第 4 周 | 复核全链路 | 优化 SQL 与索引 | 写报告初稿 |
| 第 5 周 | 一起演练答辩 | 一起演练 | PPT + 排练 |

**每周固定一次 15 分钟同步**：各自说"这周产出了什么文件、下周要什么文件"。

---

## 7. 对 A 的提醒

**你是唯一有 Java 基础的人**，所以你大概率会被默认成"技术负责人"。两件事要注意：

1. **别把 B 和 C 的活也揽过来** —— 你会写得比他们快，但那样他们答辩讲不出东西，老师会看出来
2. **把项目控制在 4 小时/周** —— 你的主线（Java SE + 集合 + IO + 后面的大数据栈）比这个项目重要。**项目里只做"能用上你正在学的东西"那部分（IO 读文件、集合分组），其余交给 B**

**反过来，这个项目对你有一个明确收益**：你会亲眼看到 **SQL 的 `GROUP BY` 就是 Java 集合分组聚合的另一种写法**。等你 W6 学 Stream 的 `groupingBy` 时，这三种写法（Java 循环 / SQL / Stream）在脑子里会连成一条线——**这是很多人工作几年都没establish的联系**。
