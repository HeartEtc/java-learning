## 1. 需求

一个控制台记账程序：

| 功能 | 说明 |
|---|---|
| 记一笔 | 日期、金额、分类、类型（收入/支出）、备注 |
| 列出全部 | 按录入顺序或按日期显示 |
| 按分类统计 | 输入分类，输出该分类总额 |
| 按月统计 | 输入 `2026-10`，输出该月收入/支出/结余 |
| 删除一条 | 按 id 删除，删除后总额必须跟着变 |
| **持久化** | **数据写入文件，程序重启后不丢** |

## 2. 关键设计决策（每条都要写理由，我给了我的判断，你可以推翻但要写明为什么）

| 决策 | 结论 | 理由 |
|---|---|---|
| 金额用什么类型？ | **`BigDecimal`** | `double` 存金额不精确：`0.1 + 0.2 != 0.3`。记账程序算错钱是致命问题。**备选**：用 `long` 存"分"，也行，但 `BigDecimal` 更通用且面试常问 |
| 分类用什么？ | **枚举 `Category`** | 字符串分类靠拼写，`"餐饮"` 和 `"餐钦"` 会变成两个分类，而且无法遍历。枚举还能防止"新增分类时忘记改统计逻辑" |
| 收入/支出用什么？ | **枚举 `RecordType`** | 同上的理由。**不要用 `boolean isIncome`**——P1 的 `available` 已经暴露过这个隐患：加第三种状态（转账、退款）时要改所有调用点 |
| 数据存什么格式？ | **CSV**（第一版） | 先用记事本能打开、能肉眼查错的格式。JSON 等第一版跑通后再加（那时正好是接口的真实用例） |
| 日期用什么？ | `java.time.LocalDate` | P1 已经用过，且能直接比较、能按月分组。**不要用 `String`**，否则按月统计要做字符串切割 |
| 容器用什么？ | `ArrayList<Record>` | P1 重构后已经验证过；不需要 Map 索引（记录量小，按 id 查找 O(n) 可接受，**但要在注释里写明这是有意选择**） |
| 文件读写放哪一层？ | **独立出 `FileStorage` 类** | `Ledger` 只管业务（增删统计），`FileStorage` 只管"对象 ↔ 文件文本"的转换。理由：以后换 JSON 只需换一个类，业务代码一行不动——**这就是 P2 引入接口的天然位置** |

## 3. 类清单

| 类 | 类型 | 职责 | 状态 |
|---|---|---|---|
| `Record` | 具体类 | 一条账目：id、date、amount、category、type、note | ⬜ |
| `RecordType` | **枚举** | `INCOME` / `EXPENSE` | ⬜ |
| `Category` | **枚举** | 餐饮 / 交通 / 学习 / 娱乐 / 工资 / 其他 | ⬜ |
| `Ledger` | 具体类 | 持有 `List<Record>`，提供增删查与统计 | ⬜ |
| `FileStorage` | 具体类 | CSV 读写：`save(List<Record>)` / `load()` | ⬜ |
| `Main` | 具体类 | 菜单循环、输入输出 | ⬜ |
| `LedgerTest` | 测试类 | 回归 + 边界测试 | ⬜ |
| `LedgerException` | 异常类 | 业务异常（如"金额非法"） | 待定，见下 |

**异常策略（沿用 P1 的判据）**：

- id 不存在 → 抛异常（调用方传了系统里没有的 id = 传参错误）
- 金额 ≤ 0、日期为 null → **抛 `IllegalArgumentException`**（参数本身非法）
- 文件损坏 / 格式不对 → 抛异常还是跳过该行？**第一版选择跳过并打印警告**，理由：一行脏数据不该让整个账本打不开。**这个决定要在代码注释里写清**

## 4. CSV 格式

```
id,date,type,category,amount,note
R001,2026-10-15,EXPENSE,餐饮,35.50,午饭
R002,2026-10-15,INCOME,工资,8000.00,十月工资
```

**要处理的坑（提前写下来）**：

| 坑 | 处理 |
|---|---|
| 备注里有逗号 | 要么禁止逗号（写入时替换成空格），要么用引号包裹。**第一版选禁止**，并在注释里写明局限 |
| 备注里有换行 | 同上，禁止 |
| 文件不存在（首次运行） | `load()` 返回空列表，**不抛异常** |
| 文件存在但为空 | 同上 |
| 编码 | 统一 UTF-8。写：`new OutputStreamWriter(new FileOutputStream(f), StandardCharsets.UTF_8)`；读同理。**不要用平台默认编码**（Windows 是 GBK，会乱码） |
| 表头行 | 要写，读的时候跳过第一行 |
| 金额解析 | `new BigDecimal(str)`，注意 `35.5` 和 `35.50` 是同一个值但 `toString` 不同——**统计比较用 `compareTo` 不要用 `equals`** |

## 5. 验收标准

- [ ] 记一笔 → 列出全部 → 能看到刚记的记录
- [ ] 退出程序 → **重新启动 → 数据还在**（P2 核心验收项，必须有自动化测试覆盖）
- [ ] 首次运行（无数据文件）不抛异常
- [ ] 手动往 CSV 里塞一行脏数据（少一列 / 金额不是数字）→ 程序跳过该行并警告，不崩
- [ ] 按分类统计：输入分类，输出总额
- [ ] 按月统计：输入 `2026-10`，输出收入、支出、结余
- [ ] 删除记录后，记录总数和总额都跟着变
- [ ] 金额用 `BigDecimal`，代码里搜不到 `double amount`
- [ ] 分类和类型是枚举，代码里搜不到 `String category` 作为字段类型
- [ ] **能用 Stream 一行写出"按分类分组求总额"**（对照执行表第 5 节验收项）
- [ ] Git 仓库 + README（做什么 / 怎么跑 / 学到什么）
- [ ] 有回归测试类，改代码后能一条命令验证没搞坏东西

## 6. 实施顺序（不要跳）

| 阶段 | 内容 | 判据 |
|---|---|---|
| **D1** | 读廖雪峰 IO：`File` / `Reader` / `Writer` / `BufferedReader` / `Files`；写一个最小 Demo | 往文件写 3 行、读回来打印；搞清"忘记 flush/close 会导致文件为空" |
| **D2** | 写 `RecordType` / `Category` / `Record`（含校验与 `toString`） | 编译通过；非法金额被拒 |
| **D3** | `Ledger`：增、列、删 + 按分类统计 | 控制台能跑通，先用内存数据 |
| **D4** | `FileStorage`：CSV 写 + 读 | **重启后数据还在**（第一天不要做别的） |
| **D5** | `Main` 菜单 + 按月统计 | 全流程手动验收 |
| **D6** | Lambda / Stream 重写统计部分 | 一行写出 `groupingBy` + `summingBy` |
| **D7** | `LedgerTest` 回归 + 边界测试 + README + push | 全部验收项打勾 |

**顺序理由**：IO 必须排在最前面，因为它是"最小可验证风险"——文件读写是 P2 唯一没做过的事，先花一天确认能跑通，比写完 500 行业务逻辑才发现存不进文件强。
